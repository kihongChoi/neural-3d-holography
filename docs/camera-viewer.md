# 카메라 실시간 뷰어

저장소 루트의 `Start-CameraViewer.cmd`를 더블클릭한다. 카메라와 스테이지를
연결하고 실제 프레임이 수신되면 레이저를 외부 동기 모드로 켠다.
창만 먼저 열려면 아래 명령에서 `--start`를 생략한다.

```powershell
.\.venv\Scripts\python.exe -m benchtop.camera_viewer --start
```

SLM에는 뷰어의 **SLM 재생** 탭이나 beamSplat 등 외부 프로그램으로 화면을 표시한다.
뷰어에서 재생 버튼을 누르기 전에는 외부 화면을 유지한다. 카메라는 SLM V-Sync의
Line0 상승 에지로 연속 촬영한다. 프레임이 오지 않으면 트리거 대기를 표시하고
마지막 영상의 경과 시간을 보여준다. 자유 실행 촬영으로 자동 전환하지 않는다.

| 조작 | 동작 |
| --- | --- |
| 시작 | 카메라 연속 취득, 레이저 외부 동기 ON, 스테이지 연결. 자동 이동 없음. |
| 스트림 중지 | 카메라 취득 종료 및 레이저 OFF. 스테이지 제어는 유지. |
| 레이저 ON / OFF | READYBeam Analog 외부 동기 / Digital·BGR Off·0% readback. |
| 노출 시간 → 노출 적용 | μs 단위. 기본 15,000 μs, 지연 22 μs. 장치 허용 범위와 100,000 μs 상한 내에서 적용. 실제 적용값 표시. |
| − 이동 / + 이동 | 장치 절대좌표 기준으로 설정한 0.5–10 mm만큼 이동. |
| 이동 속도 → 속도 적용 | 스테이지 탭에서 0.05–2.00 mm/s. 정지 중에 적용하고 장치 readback 확인. 기본 0.50 mm/s. |
| 호밍 | 역방향 홈 설정 확인 후 원점 복귀. 미호밍 상태에서는 일반 이동 불가. |
| 정지 / Esc | 진행 중 스테이지 이동·호밍 정지, 대기 중 이동 명령 취소. |
| PNG 저장 | 마지막으로 수신한 전체 센서 RGB 8-bit PNG 한 장 저장. 자동 연속 저장 없음. |
| 창 닫기 | 스테이지 정지, 레이저 OFF readback, 카메라 런타임 설정 복원 후 종료. |

스테이지는 LTS300/M `45897069`, 카메라는 FLIR `25222112`, 레이저는 READYBeam
serial `23` / firmware `2.00`을 사용한다. 카메라 전체 프레임은 4096 × 3000이다.
영상 취득은 BayerRG8 → SDK RGB8 변환이며 자동 노출·자동 이득·감마·자동 화이트밸런스는
끄고 이득 0 dB를 사용한다. 뷰어 이미지는 정량 실험용 Bayer16 원본과 구분한다.
노출 변경 시 취득을 잠시 재시작하므로 전환 구간에는 프레임이 생략될 수 있다.
짧은 노출은 RGB 한 주기를 모두 적분하지 않을 수 있다.

영상은 화면에 맞춰 종횡비를 유지해 축소 표시하며 저장은 전체 해상도다.
SDK NewestOnly와 단일 최신 프레임 버퍼를 사용한다. 수신 FPS는 장치/USB/처리 속도와
노출에 따라 달라지며, 모든 SLM 갱신을 빠짐없이 저장하는 레코더는 아니다.
카메라 실패 또는 2초 이상 프레임 중단이 감지되면 레이저 OFF를 요청한다.
트리거가 복구되어도 레이저는 ON 버튼으로 다시 켠다.

스테이지 이동 속도는 0.05–2.00 mm/s(기본 0.5), 가속도 1 mm/s²,
상한은 124 mm이며 backlash 여유까지 검사한다. 호밍 속도는 최대 0.5 mm/s로 별도 제한한다.
현재 위치는 **장치 절대좌표**다. 광학 깊이 0 mm나 SLM 공액면을 뜻하지 않는다.
호밍은 역방향/역방향 리밋 설정과 0–5 mm 홈 오프셋을 확인하고 속도를 최대
0.5 mm/s로 제한한다. 홈 설정이 예상과 다르면 실행하지 않고 오류를 표시한다.
호밍에는 현재 위치에 따라 수 분이 걸릴 수 있으며 Esc로 중단할 수 있다.
종료 시 시작 위치로 돌아가는 이동이나 좌표 리셋은 하지 않는다.

## 일반 사진을 SLM에 재생

검증 LUT는 저장소 루트 기준
`results/20261111-140112_joint-rgb-offline-lut-distillation/rgb_lut_candidate.npz`에 있다.
뷰어가 이 경로를 사용하므로 다른 PC에서도 같은 상대 경로를 유지한다.
이 NPZ와 `apply_rgb_lut.py`, `checksums.json` 세 파일은 Git 인계에 포함하며,
나머지 대용량 `results/` 데이터는 계속 제외한다.
다른 프로그램에 적용할 때는 세 파일을 같은 폴더에 두고
`load_candidate()`로 검증한 뒤 `apply_rgb_lut(original_codes, table)`을 호출한다.
입력은 기존 +π 오프셋·반전 인코딩의 HWC RGB uint8 DPAC 코드이며,
활성 영역에 한 번만 적용하고 주변 코드128을 유지한다. NumPy가 필요하다.
현재 표의 SHA256은 `034d9e8454e86190c7e1e19be64c8f44a54bb699ea5c2e9eb6e2e0add217b569`다.

1. **SLM 재생** 탭에서 보조 디스플레이를 선택한다. 현재 분배기는 `1to2`로 표시된다.
   출력은 1920×1080, Windows 배율 100%여야 한다. 주 디스플레이에는 출력하지 않는다.
2. **이미지 / 복소 NPY 선택**으로 PNG/JPG/BMP/TIFF 사진을 선택한다.
   기본 입력 방식은 **일반 사진 → 단일 패스 DPAC**다.
3. **설계 깊이**(0–20 mm, 기본 3 mm)를 입력하고 **홀로그램 생성 / 준비**를 누른다.
   설계 깊이는 광학 SLM 기준 전파 거리이며 스테이지 절대좌표와 다르다. 이 값으로 스테이지를 자동 이동하지 않는다.
4. **선택 화면에 SLM 재생**을 누른다. 사진은 선형 강도에서 비율을 유지해 맞추고,
   RGB 638/520/450 nm 단일 패스 DPAC로 변환한다. 사진 전체가 들어가며 크롭하지 않는다.
5. **LUT ON/OFF**로 같은 원본 홀로그램의 보정 전후를 전환한다.
   2026-11-11 실물 검증 공동 RGB LUT 파일의 해시·표 형식을 확인하고 정확히 한 번 적용한다.
   OFF는 항등 구동이며 토글을 반복해도 LUT가 누적되지 않는다.

출력 영역은 중앙 **1728×960**, 위치 **x=96, y=60**이며 전체 1920×1080의
**면적 80%**다. 가로·세로 각각 80%라는 뜻이 아니다. 주변은 기존 실험과 같은 코드128이다.
생성된 원본 구동 PNG와 출처/깊이/해시는 해당 실행의 `patterns/`에 보존한다.
사진 DPAC는 별도 프로세스, 복소장 DPAC는 백그라운드 작업에서 생성하므로 카메라·레이저·스테이지 제어를 막지 않는다.
사진 선택이나 생성만으로 SLM 출력이 바뀌지는 않는다(기존 뷰어 출력은 파일 교체 시 해제).

**SLM 재생 해제**를 누르면 뷰어의 출력 창을 닫아 외부 프로그램의 화면으로 돌아간다.
창 종료와 SLM 연결 해제에도 출력 창을 해제한다. 재생 직후 실제 디스플레이 픽셀을
검사하며, 가려짐/연결/배율 문제가 있으면 재생을 해제하고 상태를 표시한다.

이미 완성된 **LUT 미적용** 구동 이미지도 선택할 수 있다. 이 모드는 물리 위상 픽셀을
보존하기 위해 자동 리사이즈하지 않는다. 1728×960 이하를 중앙 배치하거나, 전체
1920×1080 구동 파일의 기존 중앙 활성 영역을 사용한다. 이미 LUT를 적용한 파일에
다시 LUT ON을 사용하지 않는다.

각 실행은 KST `results/YYYYMMDD-hhmmss_camera-live-viewer/`를 배타적으로 만든다.
`state.json`은 현재 상태, `events.jsonl`은 연결·설정·명령·종료 readback 기록이다.
요청한 PNG만 `camera/`에 저장한다. 카메라나 스테이지를 다른 프로그램에서
사용 중이면 그 장치 연결을 먼저 해제한다. 레이저의 제조사 서비스 프로그램은
기존 `benchtop.readybeam` 어댑터가 사용한다.

## 복소 CGH NumPy → DPAC PNG 저장

1. **SLM 재생 → 이미지 / 복소 NPY 선택**으로 `.npy` 파일을 연다.
   입력 모드가 **복소 CGH (.npy) → DPAC 저장**으로 자동 전환된다.
2. **복소장 DPAC gain**을 설정한다(기본 1, 범위 0.01–10).
   **홀로그램 생성 / 준비**를 누르면 PNG를 자동 저장한다. SLM 재생은 별도 버튼이다.
3. **생성 파일 저장 폴더 열기**로 해당 실행의 `patterns/0001/` 등 생성 폴더를 연다.
   `dpac_slm.png`는 중앙 80%에 배치한 **1920×1080 RGB8, LUT OFF** 파일이다.
   `original_codes.png`는 **1728×960 활성영역** 원본이고 `pattern.json`에는
   입력 파일 해시, 형상, 공통 진폭 최대값, gain, RGB 클리핑 비율과 출력 해시가 기록된다.
   뷰어의 LUT 토글은 재생에 적용되며 저장된 원본 PNG를 덮어쓰지 않는다.

입력은 **SLM 면의 복소장** `complex64`/`complex128` 배열이다.
`[3,H,W]` 또는 `[H,W,3]`의 채널 순서는 RGB다. `[H,W]`, `[1,H,W]`,
`[H,W,1]`은 같은 복소장을 RGB에 복제한다. 단일 채널의 다른 파장용 전파장은
자동 계산하지 않는다. 채널 축이 모호한 배열, 실수 강도/위상 배열, NaN/Inf는 거부한다.
pickle 및 `.npz`는 지원하지 않는다. 물체면 복소장이라면 먼저 SLM 면으로 전파해야 한다.

1728×960 이하 입력은 원래 픽셀 크기 그대로 복소 0으로 중앙 패딩한다.
1920×1080 입력은 x=96, y=60의 중앙 1728×960 영역을 사용하여 바깥 영역을 제외한다.
그 외 큰 해상도는 자동 축소하지 않고 오류를 표시한다. 입력의 물리 픽셀 간격이
SLM 격자와 이미 일치한다고 가정하며 픽셀 간격 변환 기능은 포함하지 않는다.

정규화는 **크롭 전 RGB 전체의 공통 max|U|**를 사용한다.
`A=clip(gain*|U|/max|U|,0,1)`과 `phi±acos(A)`를 체커보드로 배치하고,
기존 SLM의 +π 오프셋/반전/8-bit 양자화 규약으로 저장한다.
gain>1이면 밝은 부분이 잘릴 수 있으며 클리핑은 패딩 포함 활성영역 기준으로 표시한다.
복소장 모드에서는 설계 깊이를 사용하지 않고 추가 ASM 전파·저역 통과·조명 보정도 하지 않는다.
일반 사진의 기존 파장별 DPAC 경로와는 구분된다.

장비 없이 화면을 확인하려면 `Start-CameraViewer.ps1 -Demo` 또는
`.\.venv\Scripts\python.exe -m benchtop.camera_viewer --demo --start`를 실행한다.
DEMO 표시는 합성 영상/가상 장치이며 실제 장비 연결 실패의 대체 화면으로 쓰지 않는다.

개발 검증:

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_camera_viewer tests.test_stage_safety -v
.\.venv\Scripts\python.exe -m benchtop.camera_viewer --demo --smoke-test
```
